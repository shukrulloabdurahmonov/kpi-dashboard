Methodology

How the Search dashboard's numbers are built: two independent sources with two different definitions of a “search” — never compare volumes between them.

Source 1 — Search KPI rollups (Trino)

The funnel, trend, and category sections come from the search team's rollup tables glue.odyn_search_and_ad_ranking.daily_search_users_kpis / daily_search_volume_kpis / daily_user_searches on Trino (presto.data.olx.org), the same sources behind the production multi-country Tableau board. History starts 2024-12-30 (ISO week 1 of 2025).

  • Avg-daily semantics. Weekly and monthly users_* / volume_* values are averages of daily values, never period totals or distinct counts over the period. A weekly point of 372K search users means “on an average day of that week, 372K users searched”.
  • Funnel. Search users → same-day ad viewers → same-day repliers. Conversion percentages (search → ad view, search → reply) are unweighted averages of the daily ratios, matching the production board.
  • Per-category shares. The source computes per-category conversion ratios against ALL search users (the same-level “All” denominator), so a category's percentage is its share of all search users — not that category's own conversion rate. The dashboard labels them accordingly.
  • True totals. The only additive volume metric is searches (event count) from the daily search log, split by platform, keyword-vs-browsing, category usage, and finance category (via the eu_bi category dimension, deepest level coalesced L3 → L2 → L1).
  • Keyword vs Browsing. A search with a typed query is “Keyword”; category navigation without a query is “Browsing”. A user can do both in one day, so method shares can sum past 100%.
  • TGV is not tracked for UZ — all TGV columns in the source are legitimately 0 and are excluded from this dashboard.

Source 2 — Raw clickstream (hydra on yamato)

The region map, zero-result rates, and the keywords table come from raw hydra clickstream (hydra.web / hydra.android / hydra.ios) on the yamato warehouse. UZ retention starts 2025-07-02. A “search” here is a first-page keyword SERP view: listing-page events with a non-empty keyword, page_nb = 1, a valid result count below the 999999 app sentinel, filtered through the house-standard 17-rule bot/user-agent filter plus the eu_bi IP blacklist.

  • Zero-result (ZSR) = 0 results returned; low-supply = 1–10 results.
  • Platform asymmetry — the big caveat. Web and iOS auto-extend empty searches with fallback results, so their hard-zero rates are near 0 (~0.001%). Android reports true zeros (~15–22%). Rates are therefore never blended across platforms; the dashboard shows ZSR for Android only.
  • Regions come from the event's region_id, mapped to the same region names the rest of the app uses (via livesync.cee_olxuz_regions). SERP view counts are additive, so the map sums all platforms.
  • Keywords table: top 500 keywords per platform by 28-day search volume (minimum 30 searches), LOWER(BTRIM(keyword))-normalized, with ZSR %, low-supply % and average result count. ZSR % is only meaningful on Android.

Refresh & retention

  • Extraction runs on a scheduled machine with warehouse + Trino access each morning (~08:30 Tashkent): full Trino history plus the current and previous month of clickstream. The result ships as a data payload that this server merges into its store with its nightly rebuild.
  • Weekly and monthly search history is kept in full; daily series keep 90 days; the keywords table always holds one 28-day window.
  • If a morning extraction is missed, only this dashboard ages — the main KPI dashboard refreshes independently.
