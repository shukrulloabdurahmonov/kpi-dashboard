# Changes since 2026-08-10 — and how to update the droplet

Everything that changed on Aug 10–11, file by file, plus the update procedure.
TL;DR for the droplet: **rsync the webapp + rebuild the container + ship the
new snapshot** — three commands, listed at the bottom. The webapp changes
REQUIRE the new snapshot (new grains and metrics live in the data file), so
always ship both together.

---

## 1. Time grains: Day | Week | Month toggle (Aug 10)

Every page now has a grain toggle in the filter panel (`?grain=day|week|month`).
Cards re-bucket with grain-appropriate deltas (MoM/YoY · WoW/vs-4w · DoD/vs-7d);
trend charts re-bucket; snapshot charts (breakdown bars, map, matrix, MoM
growth) stay monthly and say so. Weekly is a real extraction grain (26 Monday-
keyed weeks, exact Redshift aggregates — WAU etc. cannot be summed from
dailies); daily expanded to full slice parity (90 days, all metrics).

**Engine (Mac-side only — droplet does not run the updater):**
- `updater/registry.py` — rewritten: one `MetricSpec` per metric family with a
  `GrainPlan` per grain (window/chunk/dims/overrides). **Spec names lost the
  `_monthly`/`_daily` suffixes** (`nnl_monthly` → `nnl`); `--only` now accepts
  `spec@grain` (e.g. `active_users@weekly`).
- `sql/*` — 23 per-grain files merged into **16 unified templates** with
  `{period_expr}` / `{date_expr}` placeholders (monthly renders proven
  byte-identical before deleting the old files). `liquidity_daily.sql` remains
  as a per-grain override.
- `updater/extract.py` — per-grain dispatch; weekly period key =
  `TO_CHAR(DATE_TRUNC('week', CAST(col AS DATE)), 'YYYY-MM-DD')` (Monday);
  Monday-aligned chunking invariant; per-grain maturity guards.
- `updater/periods.py` — `week_start` / `add_weeks` / `week_key` / `week_range`.
- `updater/main.py` — `spec@grain` targeting, stale-meta pruning, **retention
  pruning** (rows older than 24m/26w/90d are now deleted each run),
  dim-scoped meta stats.
- `updater/store.py` — `prune_old_periods`, `prune_meta`, dim-scoped
  `spec_stats`.
- `updater/probes.py` — per-grain count probes, `--weekly`, `--dates`
  (CAST-safety) probes, completed EXPECTED schema lists.
- `config/settings.py` — `WEEKLY_WINDOW_WEEKS=26`,
  `ROLLING_WEEKLY_REFRESH_WEEKS=9`.

**Webapp:**
- `webapp/data.py` — grain-generalized series/kpi/ratio/resolve
  (`series_at`, `shift_period`, `GRAIN_DELTAS`, partial-week dropping);
  `wau` added to `NON_ADDITIVE`.
- `webapp/app.py` — `current_grain()`, `GRAIN_METRIC` (mau→wau/dau),
  grain threading through every builder, grain-URL construction.
- `webapp/templates/tab.html` — segmented Day|Week|Month control; card delta
  labels come from the payload.
- `webapp/static/dashboard.js` — grain-aware period labels ("wk 3 Aug").
- `webapp/static/player.js`, `templates/player.html` — Timeline Player gained
  the week grain (+ month-preserving grain snap).
- `webapp/definitions.py` — WAU entry.

**New metric names in the data:** `wau` (weekly active users). Meta table now
keys on the 16 new spec names.

## 2. Code-review hardening (Aug 10)

Ten verified fixes from an adversarial review of the grain refactor:
- **DAU heatmap timezone bug** (`dashboard.js`) — `toISOString()` shifted every
  cell one weekday for UTC+ viewers (i.e. everyone in Tashkent). Now built
  from local date parts.
- **card() silent fallback** (`app.py`) — an empty filtered slice now shows an
  honest empty card instead of unbadged site totals.
- **derived_diff population mixing** (`app.py`) — stacked insertions charts
  now resolve both components against the same filter slice or fall back to
  totals together.
- **Retention pruning** (see above) — store/snapshot no longer grow past the
  advertised windows.
- **Weekly rolling slack** — 9 weeks (was effectively zero for the 28d-mature
  liquidity cohorts; a missed cron week could permanently lose a week).
- **Meta stats cross-contamination** — `pageviews` is written by two specs at
  different dims; stats now scoped so staleness can't be masked.
- **Player fetch race** (`player.js`) — stale responses from rapid control
  clicks are discarded (sequence token).
- Probe schema coverage completed; monthly-pinned charts labeled; plus the
  grain-aware `multi_series`/dim-discovery fixes.

## 3. Performance + loading UX (Aug 10)

- `webapp/data.py` — the heavy `DISTINCT` scans (filter options, category
  tree, page-dim discovery) are memoized **keyed by the snapshot file's
  mtime** — a newly shipped snapshot invalidates automatically. Caches
  pre-warm at app startup (`app.py`). Page renders: 12.5s cold → 0.2–0.7s.
- `webapp/static/dashboard.js` + `style.css` — spinner overlay on filter
  Apply / grain clicks / tab navigation (`.page-loading`).

## 7. ⚠️ Metric definition change: unique_repliers (Aug 11)

`unique_repliers` switched from logged-in users (`COUNT(DISTINCT user_sk)`)
to **session-based** (`COUNT(DISTINCT session_long_sk)`) — includes anonymous
callers/phone-reveals, ≈2× higher (Feb 2026: 634,864 vs 304,036). The full
history was re-extracted so trends are consistent; the Dictionary documents
the change. Reason: matches the basis of the company Tableau board — whose
own listers/repliers numbers were additionally proven inflated ~2.5× by
Tableau SUMming distinct-count cube measures across category×geography rows
(replies matched exactly once traced to `SUM(successful_event_factor)`).

- `sql/repliers.sql`, `webapp/definitions.py`.

## How to update the droplet

The droplet only runs the **webapp container + snapshot**; all updater changes
stay on the Mac. From the Mac, in this directory:

```bash
# 1) code: rsync webapp + compose, rebuild, restart  (uses config/deploy.env)
deploy/deploy.sh

# 2) data: build + ship the new snapshot (atomic swap on the droplet)
/usr/bin/python3 -m updater.main --ship-only

# 3) verify
curl https://<your-sub>.duckdns.org/health     # freshness green, new built_at
```

If you deployed manually instead of via `deploy.sh`, the complete set to copy
is: `webapp/` (all of it), `docker-compose.yml`, `deploy/Caddyfile` → then
`docker compose up -d --build` in `/srv/kpi`, and ship the snapshot.

**Compatibility notes:**
- New webapp + old snapshot: week/day toggles and funnels render empty (no
  weekly rows, no 1d columns) — ship the snapshot in the same update.
- Old webapp + new snapshot: works, but shows none of the new features and
  repliers history will look ~2× above old exports.
- No dependency changes (`requirements.txt` untouched); no env var changes;
  Docker image rebuilds from the same base.
- If any of your own scripts call the updater with `--only`, the spec names
  changed (`nnl_monthly` → `nnl`, `mau` → `active_users`, etc. — run
  `--only wrongname` to get the full list in the error message).

## Post-update sanity checklist (browser)

1. Grain toggle on Listings: Week shows WoW deltas and "wk …" axis labels.
2. Overview at Week: the Active users card reads WAU (~2.2M), not MAU (~5.8M).
3. Liquidity: two funnels at the top, NNL → 28d → 14d → 7d → 1d.
4. New "Demand vs Supply" tab with three full-width charts.
5. Unique repliers card ≈ 630K/month (session-based).
6. Filter/grain clicks show the loading spinner; repeat visits are fast.
